# TestFlight: проверка на силата на ботовете с реални хора

Ботовете са калибрирани само бот срещу бот. Преди публикуване дай TestFlight билда на 4–6 души с известен рейтинг (Chess.com, Lichess или FIDE) и събери отговорите по-долу. Отнема около 1 час на човек.

## Кого да поканиш
- 1–2 начинаещи (под 800 в Chess.com rapid)
- 1–2 средни играчи (800–1500)
- 1–2 силни играчи (над 1500)

## Какво да изиграе всеки
1. 2 партии срещу бота, чийто рейтинг е най-близо до неговия собствен рейтинг.
2. 1 партия срещу бот с ~200 точки по-слаб.
3. 1 партия срещу бот с ~200 точки по-силен.
Без подсказки и без връщане на ходове; темп по усет (ботът мисли 0,3–1,7 s на ход).

## Въпроси след всяка партия
| Въпрос | Отговор |
|---|---|
| Бот (име, рейтинг) | |
| Твоят рейтинг и сайт | |
| Резултат | победа / реми / загуба |
| Ботът изглеждаше: | много по-слаб / малко по-слаб / колкото рейтинга / малко по-силен / много по-силен |
| Имаше ли „нечовешки“ ходове (напр. перфектна игра, после подарена дама)? | |
| Точността (%) в ревюто изглежда ли правдоподобна в сравнение с Chess.com/Lichess? | |
| Беше ли интересно да играеш пак срещу този бот? | |

## Как да тълкуваш резултата
- Ако срещу „своя“ бот хората печелят ~50% — калибровката е добра.
- Ако **всички** ботове изглеждат по-слаби: увеличи `BOOST` в `www/bots.js` (сега 100) с 50–100.
- Ако само слабите ботове (под 1320) са проблем: коригирай таблицата `LOW` в `www/bots.js` (вероятността за грешка).
- Ако хората отбелязват „нечовешки“ грешки при слабите ботове — това е най-честата критика към шахматни ботове в App Store; по-добре по-малко, но по-реалистични грешки.
